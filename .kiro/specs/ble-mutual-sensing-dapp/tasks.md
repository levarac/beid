# Implementation Plan

## Tasks

- [ ] 1. Flutterプロジェクト初期化と基盤セットアップ
- [x] 1.1 Flutterプロジェクトを作成し、必要なパッケージ依存関係を設定する
  - Flutter 3.38.4でプロジェクトを新規作成する
  - hive_ce、reown_appkit、flutter_secure_storageなどの依存パッケージを追加する
  - iOS/Androidのプラットフォーム固有設定（BLEパーミッション、Info.plist、AndroidManifest.xml）を構成する
  - 環境変数管理（Reown Project ID等）の仕組みを導入する
  - _Requirements: 1.4, 1.5_

- [x] 1.2 (P) アプリケーションのレイヤー構造とDI基盤を構築する
  - サービス層、リポジトリ層、UI層のディレクトリ構造を作成する
  - 依存性注入（Provider/Riverpod等）の基盤を設定する
  - 共通のResult型、エラー型の基底クラスを定義する
  - _Requirements: 1.1, 2.1_

- [ ] 2. 独自BLEライブラリ連携とBLEサービス実装
- [x] 2.1 独自BLEライブラリとのインターフェース合意とモック実装を作成する
  - 独自BLEライブラリが提供すべきインターフェースを定義・合意する
  - ライブラリ完成前に開発を進めるためのモック実装を作成する
  - スキャン開始/停止、アドバタイズ開始/停止の基本操作をモックで再現する
  - _Requirements: 1.1, 1.2_

- [x] 2.2 BLEサービスを実装し、スキャンとアドバタイズを統合管理する
  - 独自BLEライブラリを使用してBLEスキャンを開始・停止する機能を実装する
  - 同時にBLEアドバタイズを開始・停止する機能を実装する
  - ウォレットアドレスからユニークなBLE UUID（サービスUUID）を生成するロジックを実装する
  - 検知したデバイスのUUIDとRSSIをストリームで提供する
  - _Requirements: 1.1, 1.2, 1.3_

- [x] 2.3 BLE状態監視とパーミッション管理を実装する
  - Bluetooth有効/無効状態を監視しストリームで通知する
  - BLEパーミッションの確認と要求フローを実装する
  - BLE無効時やパーミッション拒否時のエラー状態を適切に伝播する
  - _Requirements: 1.4, 1.5_

- [x] 3. ウォレットサービス実装
- [x] 3.1 (P) Reown AppKitを使用したウォレット接続機能を実装する
  - Reown AppKitを初期化し、Project IDとサポートチェーン（Gnosis Chain）を設定する
  - ウォレット接続モーダルを表示し、WalletConnect経由で接続を確立する
  - 接続成功時にウォレットアドレスとchainIdを取得・保存する
  - _Requirements: 6.1, 6.2_

- [x] 3.2 (P) ウォレット切断とセッション管理を実装する
  - ウォレット切断機能を実装し、セッションをクリアする
  - アプリ再起動時に既存セッションを復元するロジックを実装する
  - 接続状態の変更をストリームで通知する
  - _Requirements: 6.3, 6.4_

- [x] 3.3 メッセージ署名機能を実装する
  - センシングレポート送信時に使用する署名機能（EIP-191 personal_sign）を実装する
  - 署名リクエストをウォレットアプリに送信し、署名結果を取得する
  - _Requirements: 3.1_

- [x] 4. センシングリポジトリとローカルストレージ実装
- [x] 4.1 (P) Hiveを使用したローカルストレージ基盤を構築する
  - Hive（hive_ce）を初期化し、SensingRecord用のBoxを定義する
  - SensingRecordのHiveアダプターを作成する
  - 履歴データの読み書き・削除の基本操作を実装する
  - _Requirements: 5.1, 5.2_

- [x] 4.2 センシングリポジトリを実装し、検知情報の管理を行う
  - BLE検知情報を一時的に保存するロジックを実装する
  - 検知情報にタイムスタンプを自動付与する
  - 履歴ストリームを提供し、UIにリアルタイム更新を通知する
  - _Requirements: 2.1, 2.4, 5.1_

- [x] 4.3 履歴データのクリーンアップ機能を実装する
  - 指定期間より古い履歴データを自動削除する機能を実装する
  - クリーンアップ設定をユーザーが変更できるようにする
  - _Requirements: 5.3_

- [ ] 5. バックエンドAPI実装
- [ ] 5.1 (P) Node.js/Expressでバックエンドプロジェクトを初期化する
  - Express.jsプロジェクトを作成し、基本的なミドルウェアを設定する
  - 環境変数管理（POAP APIキー等）を設定する
  - CORSとセキュリティヘッダーを設定する
  - _Requirements: 3.1_

- [ ] 5.2 センシングレポート受信APIを実装する
  - POST /api/sensing/report エンドポイントを実装する
  - リクエストのバリデーション（userUuid, walletAddress, partnerUuid, timestamp, rssi, signature）を行う
  - EIP-191署名を検証し、ウォレットアドレスを復元して照合する
  - センシングレポートをデータベース/メモリに保存する
  - _Requirements: 3.1, 3.4_

- [ ] 5.3 相互センシング突合ロジックを実装する
  - 受信したレポートをパートナーUUIDでマッチングする
  - タイムウィンドウ（5分以内）で両者のレポートが揃ったら相互センシング成立と判定する
  - 検証結果（成立/未成立）をレスポンスとして返す
  - _Requirements: 2.2, 3.1_

- [ ] 5.4 POAP発行連携を実装する
  - 相互センシング成立時にPOAP APIを呼び出してPOAPを発行する
  - 両ユーザーのウォレットアドレスに対してそれぞれPOAPをミントする
  - トランザクションハッシュを取得し、レスポンスに含める
  - _Requirements: 3.2, 3.3_

- [ ] 5.5 センシングステータス照会APIを実装する
  - GET /api/sensing/status/:id エンドポイントを実装する
  - レポートIDに対応するステータス（pending/verified/poap_issued/failed）を返す
  - _Requirements: 3.3, 3.4, 3.5_

- [x] 6. FlutterアプリからバックエンドAPI呼び出し
- [x] 6.1 バックエンドAPIクライアントを実装する
  - センシングレポート送信のHTTPクライアントを実装する
  - レスポンスのパース、エラーハンドリングを実装する
  - ステータスポーリングまたはWebSocket通知の仕組みを検討・実装する
  - _Requirements: 3.1, 3.3_

- [x] 6.2 センシングリポジトリとバックエンドAPIを連携する
  - BLE検知後、署名付きセンシングレポートをバックエンドに送信するフローを実装する
  - バックエンドからの検証結果を受け取り、ローカルのSensingRecordステータスを更新する
  - POAP発行完了時にtxHashをローカルに保存する
  - _Requirements: 2.2, 3.1, 3.2, 3.3_

- [x] 7. ホーム画面UI実装
- [x] 7.1 センシング開始/停止ボタンとステータス表示を実装する
  - センシング開始/停止を切り替えるFABを配置する
  - 現在のセンシング状態（スキャン中/待機中）を視覚的に表示する
  - BLE無効時やパーミッションエラー時のダイアログを表示する
  - _Requirements: 4.1, 4.2, 1.4, 1.5_

- [x] 7.2 検知ユーザー一覧を表示する
  - BLEで検知した周囲のユーザーをリスト表示する
  - RSSI（信号強度）を視覚的にインジケータで表示する
  - リアルタイムで検知リストを更新する
  - _Requirements: 4.3, 1.3_

- [x] 7.3 ウォレット接続UIを実装する
  - AppBarまたはヘッダーにウォレット接続ボタンを配置する
  - 接続中はウォレットアドレス（短縮表示）を表示する
  - 切断ボタンと接続エラー時の再試行オプションを提供する
  - _Requirements: 4.6, 6.1, 6.3, 6.5, 6.6_

- [x] 8. 履歴画面UI実装
- [x] 8.1 センシング履歴一覧を表示する
  - 相互センシング・POAP発行履歴をリスト形式で表示する
  - ステータス（検知/検証中/POAP発行済/失敗）をアイコンと色で視覚化する
  - 時系列順（新しい順）でソートして表示する
  - _Requirements: 4.4, 2.3_

- [x] 8.2 履歴詳細表示を実装する
  - 履歴アイテムタップで詳細ボトムシートを表示する
  - パートナーUUID、タイムスタンプ、RSSI、POAP発行ステータス、txHashを表示する
  - POAP発行済みの場合、外部POAPアプリへの誘導リンクを表示する
  - _Requirements: 4.5, 3.3, 3.6_

- [ ] 9. 統合テストとE2Eフロー検証
- [ ] 9.1 サービス層の単体テストを作成する
  - BLEServiceのモックを使用した状態遷移テストを実装する
  - WalletServiceの接続/切断フローテストを実装する
  - SensingRepositoryの履歴CRUD操作テストを実装する
  - _Requirements: 1.1, 1.2, 6.1, 6.3, 2.1, 5.1_

- [ ] 9.2 バックエンドAPIの統合テストを作成する
  - センシングレポート受信→検証→POAP発行の一連のフローをテストする
  - 署名検証の成功/失敗ケースをテストする
  - タイムウィンドウ外のレポートが拒否されることをテストする
  - _Requirements: 3.1, 3.2, 3.4_

- [ ] 9.3 E2Eフローの動作確認を行う
  - 2台のデバイスでセンシング開始→相互検知→POAP発行の完全フローを検証する
  - ウォレット接続→センシング→履歴確認の一連の操作を検証する
  - エラーケース（BLE無効、ネットワーク障害等）の挙動を確認する
  - _Requirements: 1.1, 2.2, 3.2, 3.3, 6.1_

- [ ] 10. 三点測位バックエンド実装
- [ ] 10.1 (P) RSSIデータ収集エンドポイントを実装する
  - POST /api/rssi/report エンドポイントを実装する
  - RSSIレポートのバリデーション（userId, detectedUsers配列）を行う
  - インメモリストア（Map）でRSSIデータを保存する
  - 古いデータの自動クリーンアップ（30秒以上経過したデータを削除）
  - _Requirements: 7.4_

- [ ] 10.2 三点測位エンジンを実装する
  - RSSIから距離への変換ロジックを実装する
  - 距離行列を構築するロジックを実装する
  - MDS（多次元尺度構成法）アルゴリズムを実装する
  - 各ユーザー視点での相対角度を計算するロジックを実装する
  - _Requirements: 7.1, 7.6_

- [ ] 10.3 (P) WebSocketサーバーを実装する
  - wsパッケージを使用してWebSocketサーバーを構築する
  - クライアント接続管理（接続/切断/認証）を実装する
  - 位置情報ブロードキャスト機能を実装する
  - ユーザー参加/離脱通知機能を実装する
  - _Requirements: 7.5, 8.2, 8.3_

- [ ] 10.4 定期的な位置計算とブロードキャストを実装する
  - 5秒間隔で三点測位計算を実行するスケジューラを実装する
  - 3人以上の場合は計算結果を配信、2人以下の場合はフォールバック通知を送信する
  - 計算失敗時のエラーハンドリングを実装する
  - _Requirements: 7.1, 7.5, 7.6_

- [ ] 11. Flutter位置サービス実装
- [ ] 11.1 (P) WebSocketクライアントを実装する
  - web_socket_channelパッケージを使用してWebSocket接続を実装する
  - 接続状態の管理（disconnected/connecting/connected/reconnecting）を実装する
  - 自動再接続機能（指数バックオフ）を実装する
  - _Requirements: 8.1, 8.4_

- [ ] 11.2 PositionServiceを実装する
  - WebSocket経由で位置更新を受信しストリームで提供する
  - RSSIレポート送信機能を実装する
  - 三点測位有効/無効状態を管理する
  - _Requirements: 7.2, 8.1_

- [ ] 11.3 BLEServiceとPositionServiceを連携する
  - センシング開始時にWebSocket接続を開始する
  - 5秒間隔でRSSIデータをバックエンドに送信する
  - センシング停止時にWebSocket接続を切断する
  - _Requirements: 7.4, 8.1_

- [ ] 12. レーダーUI拡張
- [ ] 12.1 RadarPainterを三点測位対応に拡張する
  - サーバーから受信した角度データを使用してユーザーを配置する
  - 三点測位無効時はフォールバック表示（ハッシュ値ベースの角度）を使用する
  - 位置更新のアニメーションを実装する
  - _Requirements: 7.2, 7.3, 7.6_

- [ ] 12.2 接続状態インジケータを追加する
  - WebSocket接続状態をUIに表示する
  - 三点測位有効/無効状態をUIに表示する
  - アクティブユーザー数を表示する
  - _Requirements: 8.1, 8.5_

- [ ] 12.3 オフラインフォールバックを実装する
  - WebSocket切断時はローカルのRSSIデータのみで表示を継続する
  - オフライン状態を視覚的に表示する
  - _Requirements: 8.5_
